# Процесс выпуска версий

## Версионирование
Используется Semantic Versioning:
- MAJOR — несовместимые изменения;
- MINOR — новая совместимая функциональность;
- PATCH — исправления.

До стабильной версии: 0.1.0-alpha.1, 0.2.0-alpha.1, 0.5.0-beta.1, 1.0.0.

## Типы релизов
- Alpha — ранняя проверка, возможны существенные ошибки.
- Beta — функции в основном реализованы, идёт интеграционное тестирование.
- Release Candidate — проверка готовности.
- Stable — пройдены критерии приёмки.

Alpha и beta публикуются как GitHub Pre-release.

## Перед публикацией
- рабочее дерево чистое;
- изменения находятся в правильной ветке;
- CHANGELOG обновлён;
- версии Unity и пакетов задокументированы;
- применимые тесты из TEST_PLAN.md пройдены;
- известные ограничения перечислены;
- сторонние лицензии соблюдены;
- сборка проверена на целевом оборудовании;
- в артефактах нет секретов и персональных данных.

## Публикация
1. Создать Git-тег версии.
2. Создать GitHub Release по тегу.
3. Для alpha/beta включить Pre-release.
4. Добавить описание изменений и известных проблем.
5. Прикреплять Windows build только после проверки сборки и контрольной суммы.
6. Не прикреплять SDK и сторонние бинарные компоненты без разрешения лицензий.

## Откат
При критической ошибке отметить релиз как проблемный, описать влияние и выпустить исправляющий PATCH. Не переписывать опубликованный тег без серьёзной причины.

# Техническое задание

**Статус:** Draft — требования для согласования.

## 1. Назначение

Создать учебное Windows PCVR-приложение, выводящее окно FPV-симулятора с ноутбука на виртуальный монитор в Meta Quest 3 и моделирующее характерные визуальные помехи аналогового видеоканала.

Программа не излучает радиопомехи, не вмешивается в RF-канал и не выдаёт симулируемые показатели за измерения реального оборудования.

## 2. Целевая конфигурация

Windows 10/11, Meta Quest 3, имеющийся USB-A–USB-C или USB-C–USB-C кабель, Meta Quest Link и Windows PCVR-приложение. Любой совместимый FPV-симулятор, окно которого можно захватить.

Разъём USB-C сам по себе не гарантирует нужную скорость. Кабели и порты подлежат проверке Meta Quest Link USB Test.

## 3. Функциональные требования

### FR-01. Проводное подключение
- Штатный режим — USB через Meta Quest Link.
- Wi-Fi, Air Link и облачная передача не используются.
- Приложение показывает состояние XR/Link и сообщает об отсутствии гарнитуры.

### FR-02. Захват окна
- Пользователь выбирает окно Windows, прежде всего окно FPV-симулятора.
- Обрабатываются закрытие окна, смена разрешения и ошибки захвата.
- Чёрное изображение, реально выдаваемое симулятором, не считается потерей источника.
- Захват защищённых окон не гарантируется.

### FR-03. Виртуальный монитор
- Изображение отображается на виртуальной панели перед пользователем.
- Основной режим — head-locked: панель следует за поворотами/наклонами головы и остаётся перед взглядом.
- Настраиваются размер, расстояние, вертикальное и горизонтальное положение.
- Есть команда центрирования.
- Настройка панели не перезапускает захват.

### FR-04. Passthrough
Желаемая функция: видеть физическое пространство, клавиатуру и органы управления через Passthrough при сохранении виртуального монитора. Passthrough over Link требует проверки на целевом комплекте и не считается гарантированным. Если Passthrough обязателен для занятий, успешное испытание является блокирующим критерием архитектуры.

### FR-05. Аналоговые помехи
Каждый эффект регулируется независимо и может быть полностью отключён. Есть общий выключатель всех искусственных эффектов.

Обязательные эффекты:
1. **Шум и рябь** — интенсивность, плотность, масштаб и скорость изменения.
2. **Горизонтальные полосы** — тонкие и сравнительно редкие; настраиваются частота, толщина, контраст и интенсивность.
3. **Искажение цветов** — тон, насыщенность и интенсивность.
4. **Цветовое расслоение / эффект 3D-очков** — красный контур смещается в одну сторону, синий в противоположную. Начальный пресет: красный вверх-влево, синий вниз-вправо. Настройки: направление, смещение X/Y, интенсивность.

Эффекты можно комбинировать.

Не реализовывать цифровую блочную пикселизацию, искусственное замирание изображения, потерю кадров, задержку или намеренное снижение плавности.

### FR-06. OSD Editor
Пользователь может:
- включать/отключать элементы;
- менять их положение, размер, цвет, прозрачность и выравнивание;
- сохранять, загружать и сбрасывать профили.

Начальный набор: TIMER, RSSI, VOLTAGE, CHANNEL, MODE, LINK QUALITY.

Показатели RSSI, напряжения, канала, режима и качества связи не считаются реальными без источника телеметрии. Демонстрационные или вручную задаваемые значения маркируются как симулируемые.

Для реалистичного аналогового тракта OSD накладывается на исходное изображение до применения помех, поэтому эффекты могут затрагивать OSD.

### FR-07. NO SIGNAL
- Появляется только при подтверждённой потере источника или потока захвата.
- Причины: окно закрыто, сессия захвата завершилась, источник недоступен или кадры не поступают дольше установленного порога.
- Чёрное содержимое кадра само по себе не является причиной.
- Искусственные эффекты не вызывают NO SIGNAL.
- После восстановления источника изображение возвращается без перезапуска, если это поддерживается.

### FR-08. Профили
Хранят настройки монитора, OSD, эффектов и сценариев в версионируемом JSON. Повреждённый или несовместимый профиль вызывает понятную ошибку и безопасное значение по умолчанию.

### FR-09. Интерфейс
Основная настройка выполняется на ноутбуке: статус XR/Link, выбор источника, монитор, OSD, эффекты, сценарии и диагностика. VR-интерфейс не должен закрывать учебное изображение.

## 4. Нефункциональные требования

- Не добавлять искусственную задержку; измерять фактическую end-to-end задержку на оборудовании.
- Стремиться к устойчивой частоте захвата и VR-рендеринга; конкретную цель FPS определить после прототипа.
- Не блокировать XR render loop ожиданием кадра захвата.
- По возможности выполнять обработку на GPU и минимизировать копирование кадров.
- Обеспечить стабильность в течение типичного учебного занятия.
- После настройки интернет не требуется для штатной работы.
- Поддерживаемые версии Windows, Unity, Link и пакетов фиксируются после испытаний.
- Первый язык интерфейса — русский; предусмотреть возможность локализации.

## 5. Логи и диагностика

Логировать инициализацию XR, статус Link, старт/остановку захвата, смену источника/разрешения, ошибки и восстановление. Не записывать видеосодержимое и персональные данные по умолчанию.

## 6. Критерии приёмки

1. Quest 3 подключается по USB Link на согласованном наборе кабелей.
2. Windows-приложение запускается как PCVR.
3. Выбранное окно симулятора отображается на виртуальном мониторе.
4. Монитор остаётся перед пользователем при повороте головы.
5. Настраиваются размер и положение.
6. Работают четыре согласованных типа аналоговых эффектов.
7. Эффекты отключаются по отдельности и общим выключателем.
8. OSD редактируется и сохраняется.
9. NO SIGNAL появляется только при подтверждённой потере источника/потока.
10. Чёрный кадр не вызывает ложную потерю.
11. Приложение восстанавливает изображение после восстановления источника.
12. Passthrough подтверждён, если он обязателен для учебного сценария.

## 7. Не входит в первую версию

Wi-Fi, HDMI-карты захвата, отдельный APK, реальные RF-помехи, связь с физическим радиоканалом, автоматическая телеметрия полётного контроллера, пикселизация, фризы, искусственная задержка, облачная инфраструктура.
